**Collect can keep every texture of a game, and tells you how much that is first.**

## What changed
- **Every texture of the game.** Collect › Model packages has a new option when you collect a whole game: *Every texture of the game*. Ticking it lists every texture the game's folders hold, not only the ones its models use. It then says how many aren't kept yet and about how much space they'll take, measured from a sample, before anything is written. They go into the game's asset store, still compressed as the game keeps them, so the texture picker can offer all of them after the game is uninstalled. Running it again only adds what's new. If every model is imported already, it keeps just the textures.
- **Every game's textures are kept as DDS files.** Borderlands (all six games), Returnal and Cyberpunk textures are now stored in packages still compressed, as the game keeps them, instead of decoded and saved again as PNG pictures. That's smaller, and nothing has to be decoded and encoded while importing. FromSoftware and RE Engine textures were already kept this way.
- **The texture picker lists more games.** It now finds textures in Borderlands, the Unreal games (Borderlands 3, Wonderlands, Borderlands 4, Returnal) and Cyberpunk folders too, not only FromSoftware and RE Engine ones. A Cyberpunk texture is listed under its full depot path.
- **An imported game's Collect plan.** Opening Collect for a game whose models are all imported now says so, instead of showing an error.

What isn't listed: FromSoftware textures kept only inside model archives (importing the models keeps those), Unreal textures whose names don't start with `T_`, and Cyberpunk textures that nothing in the game refers to by name, since archives keep only hashes. For a Cyberpunk folder scanned by an earlier version, the first time you keep every texture each archive is read through once more to learn the textures' names, which can take a few minutes. Until then, the texture picker lists only loose Cyberpunk textures from such a folder.

## Windows
- **`DarkSTL_0.34.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.34.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.
