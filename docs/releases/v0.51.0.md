**Grand Theft Auto V opens in Dark STL, the original release and Enhanced.**

## What changed
- **A new importer for GTA V (PC).** Add the game's install folder as it is (the one with `GTA5.exe`). Dark STL reads the models straight from the game's `.rpf` archives, nested archives, the `update` archive and DLC packs included (an update's copy of a file wins over the original). Nothing in the game's folder changes.
- **The archive keys come from your own game.** GTA V's archives are encrypted, and the keys are in the game's executable. Dark STL doesn't include them. The first time you add the folder, it reads through your `GTA5.exe` once to find them (this takes a while; the status bar shows how far it is) and keeps them in its settings folder (`keys\gta5.bin`), so it doesn't need to look again. If they can't be found, the folder note says what is missing.
- **Both layouts.** The Enhanced edition changed how textures, shaders and vertices are stored inside the files. Dark STL tells each file's layout by its version and reads both, so a folder can mix them.
- **Sorted and named as in the game.** Vehicles are grouped by class (Super, Sports, SUVs...) and named from `vehicles.meta` and the game's text (Truffade Adder, not `adder`). Weapons are named and grouped from `weapons.meta`. Characters are grouped by kind (ambient men and women, gangs, story characters, online characters' components). Props and map pieces are grouped by the archive they come from. Low-detail copies are left out.
- **Vehicles come out whole.** The game keeps one front and one rear wheel and copies them to each corner as it draws the car. Dark STL does the same, the right-hand wheels turned to face out, and places doors, bonnet and other pieces at their bones. Textures come from the vehicle's own dictionary, its parents (`gtxd.meta`) and the shared `vehshare` dictionaries.
- **Characters are outfits.** A ped's `.ydd` holds one model per component (head, top, legs, feet, hair, accessories...). Each ped is listed as a configurable model with a slot per component, so you can choose what it wears. One component on its own opens too (pick it from the model's variants).
- **Characters can be posed.** The Pose tab offers the game's clips (`.ycd`) that move the ped's skeleton, and the walk's movement across the ground is taken out so the figure stays in place.
- **Collect and packages.** Collect copies a model, its texture dictionaries, its ped skeleton and clips out of the archives as the resource files OpenIV exports, plus the game's lists and text, under their archive paths. The collected copy opens, is named and poses without the game and without the keys. Packages work as for the other games.
- Files exported with OpenIV or CodeWalker (`.ydr`, `.ydd`, `.yft` with their `.ytd`) open too, without the game.

## Not done yet
Vehicle paint isn't applied (the game picks the colours at run time, so painted panels show their base texture). Ped texture variations (the `_b_`, `_c_`... textures) aren't offered yet; each component shows its first. Weapon attachments, map placement, cloth and damaged vehicle meshes are not read. GTA IV is next, then the console and mobile releases.

This has only been tested on synthetic files built byte by byte: a GTA V folder with an executable holding made-up keys, an NG-encrypted archive with nested ones, a car, a ped with four components and clips, a weapon, a prop, and their textures, lists and text, in both layouts. Nothing has been checked against the real game yet, so the key search in a real `GTA5.exe` is still to be tried.

## Windows
- **`DarkSTL_0.51.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.51.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.51.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
