Cyberpunk 2077 joins the games Dark STL reads.

## What changed
- **Cyberpunk 2077.** Add the game's install folder as it is: its models are read straight from the `.archive` files (the first scan reads through them once to learn the models' names, and keeps what it found), grouped as weapons, clothing (by slot), characters, vehicles and objects. A folder of `.mesh` and `.xbm` files exported with WolvenKit, kept under their `base\...` paths, works too, and a model's textures are looked up in the loose folder first, then in the archives. Materials follow their `.mi` chains to the shader, so base colour, normal, roughness and detail normal maps are found by what the shader calls them; a model's appearances are offered as its variants; the levels of detail a mesh carries are listed as parts, with only the full level kept by default. Many-layered materials (skin, worn metal) are not blended: their global normal map is used and the model says so.
- **Oodle.** Cyberpunk's own `bin\x64\oo2ext_7_win64.dll` is found by itself (and the WolvenKit `kraken.dll` is accepted too); Settings > Oodle names both games' libraries.
- **Collect** copies a Cyberpunk model, its materials and textures out of the archives under their depot paths, and the game's Oodle library with them.

## Windows
- **`DarkSTL_0.7.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.7.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.7.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
