**Returnal support.**

## What changed
- Dark STL now reads Returnal (PC). Add the game's install folder as it is (the one with `Returnal\Content\Paks` in it): the models are read straight from its `.pak` files, nothing has to be extracted first.
- Models are listed by their names (`SK_`, `SKM_`, `SM_`). Packages whose names don't say what they hold are checked once by reading their header; what was read is kept, so later scans are quick until the game updates.
- They're grouped by the game's folders: Weapons, Characters (Selene, and Creatures for the enemies and bosses), Faces & Hair, Map Pieces (the biomes) and Objects. Materials, textures (colour and normal maps), Collect and every Generate step work as for the other Unreal games.
- Dark STL doesn't come with Returnal's AES key. If the game's paks are encrypted, the folder says so: paste the key (0x followed by 64 hexadecimal digits) in Settings under *Unreal games*, or put it in `unreal-keys.txt` in the game folder, then Rescan.

Built on the Unreal 4 readers from the Borderlands 3 support. Tested on synthetic paks laid out like Returnal's (plain, compressed, encrypted); not yet tried on the game's own files, so the groups may need tuning once real folder names are seen.

## Windows
- **`DarkSTL_0.25.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.25.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.25.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
