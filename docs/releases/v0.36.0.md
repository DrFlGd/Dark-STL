**Unreal models can now be posed with the game's animations** (Returnal, Borderlands 3, Tiny Tina's Wonderlands, Borderlands 4).

## What changed
- **Pose tab for Unreal 4/5 characters and creatures.** A skeletal mesh lists every animation made for its skeleton (the game's `AnimSequence` assets that use the same `Skeleton` asset), and can be held at any frame of any of them, like FromSoftware and RE Engine models. Generate, Export, the cut and paint tools and model packages all use the pose.
- **Finding a model's animations.** The first time you open the Pose tab for a game, Dark STL reads the header of each package that looks like an animation (named `A_`, `AS_`, `Anim_`... or kept in an animation folder) to see which skeleton it belongs to. That can take a minute on a big game; what it finds, and each animation's length, is kept, so later models list theirs at once.
- **What is read.** Animations compressed with Unreal's own codecs (fixed or variable key spacing and per-track compression, with every key format but one rarely used one), in the layouts of Unreal 4.12 to 5.x. Animations compressed with the **ACL plugin** are not read yet: the Pose tab says how many there are, so if a model shows that note, tell me and I'll add ACL next.
- **How the pose is made.** Rotations come from the animation; each bone keeps the mesh's own length, moved by the animation's change, so a mesh that shares a skeleton with others of other proportions keeps its shape. The root's travel across the floor is left out (the model stays in place, rising and falling with the animation). Additive animations (offsets meant to be layered on another one) are shown on the bind pose and marked as additive.
- **Returnal without a `.usmap`.** Returnal cooks its objects without property names. The skeleton's and the animations' own data are found past their properties, the frame count from the animation's header; the frame rate is then taken as Unreal's default 30 frames a second (a `.usmap` gives the real length).
- **Collect keeps it working without the game.** Collecting an Unreal model with *Animations* on now copies its Skeleton and its animations too (game files), or keeps the sampled animations in its model package, so posing still works once the game is uninstalled.
- **Skin weights.** Unreal skeletal meshes now carry their bone weights, which model packages need to pose them.

Tested on byte-built packages in each layout (4.20, 4.22, 4.24, 4.25, 4.26; versioned and unversioned without type mappings; float, interval-quantised and per-track keys), Collect to files and to packages with the game deleted. Not yet checked on real game files.

## Windows
- **`DarkSTL_0.36.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.36.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

pip install "dark_stl-0.36.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
