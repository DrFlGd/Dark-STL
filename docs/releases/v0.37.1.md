**Finding Returnal's animations, and saying why when none are found.**

## What changed
- **Animations that aren't named like animations are found.** Dark STL used to look only at packages named `A_`, `AS_`, `Anim_`... or kept in an animation folder. Returnal may name its animations otherwise, so for Returnal (and any Unreal game where nothing named like an animation is one), when a model's skeleton has none by name, Dark STL now looks through every package whose name and folder don't say it is something else (textures, materials, sounds, meshes...). This happens once per game and can take a few minutes the first time; what it finds is kept, so later models list theirs at once.
- **The Pose tab says why no animations are listed.** Instead of only "No animations were found", it now says what was looked through and what was found instead: how many packages it read, how many are animations and which skeletons they belong to, other animation assets (montages, blend spaces...) and assets made for the model's skeleton, packages that couldn't be read, paks that need another AES key, and animations compressed with the ACL plugin (not read yet). For a model that can't be posed at all (its skin weights couldn't be read, or it is a static mesh), it says that.
- **A game's own kind of AnimSequence** (a class named `...AnimSequence`) is read like Unreal's own.

Tested on byte-built Returnal packages whose animations have no prefix and sit outside any animation folder, and on a model whose skeleton has none. Not yet checked on real game files.

## Windows
- **`DarkSTL_0.37.1_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.37.1_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.
