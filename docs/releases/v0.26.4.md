**Returnal models open without a type mappings file.**

## What changed
- Returnal's PC executable is protected, so UE4SS can't dump its type mappings (`.usmap`), and 0.26.2 needed one to open any model. Dark STL now opens Returnal models without it:
  - **Meshes:** the object's unnamed properties are stepped over by finding where the mesh's own data starts (cooked flags, its bounds, material references to the package's own imports), so the geometry and material slots read as usual. A static mesh's material slots, which sit among the properties, are picked out of them.
  - **Textures:** found the same way, from their cooked header and pixel format. Two-channel (BC5) textures count as normal maps.
  - **Materials:** a material's parameters can't be read without the mappings, so its textures (and its parent material's) are sorted into colour, normal and other maps by their names (`_D`, `_N`, ...). The material is marked as guessed.
- A `.usmap`, if you do get one, is still used and reads the materials' own parameters. Mappings that don't cover a class fall back to the same search.

Tested on synthetic unversioned Returnal packages (a skeletal and a static mesh, a material instance and its textures), with and without mappings.

## Windows
- **`DarkSTL_0.26.4_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.26.4_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:
