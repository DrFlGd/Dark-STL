**Returnal's animations are read: the fix for "couldn't be read (not an animation's data)".**

## What changed
- **Unreal 4/5 animations now read on real game files.** Every animation asset stores its skeleton's ID (a 16-byte GUID) just before its keys. Dark STL started reading the keys at that ID, so every animation it found failed with *"couldn't be read (not an animation's data)"*. Jerred's Hulk showed this with 47 animations. Dark STL now reads past the ID, and still reads a file that leaves it out. This affects Returnal, Borderlands 3, Wonderlands and Borderlands 4.
- **Animations that a previous version recorded as unreadable are read again** the next time a model's Pose tab lists them. The game's packages aren't searched again.

Tested on byte-built packages that now carry the skeleton's ID as the game's do, and on packages without it. Not yet checked on real game files.

## Windows
- **`DarkSTL_0.38.1_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.38.1_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.
