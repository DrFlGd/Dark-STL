**Collected games work without the game installed.**

## What changed
- Collect now opens every model it copies, and every part and skin of a configurable gun, and records each file and archive piece the app reads while doing so. All of it is copied (or written out on its own, for a piece of a `.pak`, `.archive` or Unreal container), so the collected copy shows the same models, textures, poses, gun parts and skins once the game is uninstalled.
- Borderlands 2 and The Pre-Sequel: the packages a gun's materials and skins come from (Startup, Engine, the `GD_` part definitions, the skin packages, DLC packages) are copied with it, and only the texture caches (`.tfc`) it actually uses, instead of every cache in the folder. Skin colours are baked from the copies.
- Borderlands 4 (and other games read from IoStore containers): the containers a model is read from are copied, so it opens from the copy.
- The configurable models collected (guns with their parts and skins, Cyberpunk weapons and their attachments, Resident Evil characters) are kept beside the copies in `collected.darkstl-configs.json`, naming the copies, so their Configure menus are the same as before.
- Collecting a whole game reads each model once more than before, so working out what to copy takes a little longer.

Each game family is tested the same way: collect everything, move the game folder away, start fresh, and open every model, texture, animation and gun configuration from the copy alone, comparing what it shows with what the game showed.

## Windows
- **`DarkSTL_0.26.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.26.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.26.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
