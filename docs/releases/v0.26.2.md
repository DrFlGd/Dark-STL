**Returnal models open: unversioned packages and type mappings.**

## What changed
- Returnal cooks its packages "unversioned": they carry no engine version and store their objects without property names, so 0.25.0 stopped with *"is an unversioned package (it needs the game's type mappings)"*. Dark STL now reads the engine release Returnal was built with from the game's executable (`Returnal-Win64-Shipping.exe`) and reads the packages with it.
- Their objects still need the game's **type mappings**: a `.usmap` file made for the installed version of Returnal. None is published, so dump one from the running game with [UE4SS](https://github.com/UE4SS-RE/RE-UE4SS) (press Ctrl+Numpad 6 in game; it writes `Mappings.usmap`). Then put it in the game folder (or in `Returnal\Content\Paks`), or add it in Settings under *Unreal games*. Until it's there, the Returnal folder shows a note saying so, and opening a model tells you what's missing.
- When several games' mappings sit in the settings folder, each game takes its own: files named for a game (`Returnal.usmap`, `BL4.usmap`) go to that game, and Borderlands mappings (full of `Oak` types) aren't used for Returnal. A second `Mappings.usmap` added in Settings no longer overwrites the first.
- The library scan also reads the class of Returnal packages whose names don't say they're meshes, so more models are listed.

Tested on synthetic unversioned packages with a synthetic `.usmap`; not yet on the game's own files.

## Windows
- **`DarkSTL_0.26.2_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.26.2_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.26.2-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
