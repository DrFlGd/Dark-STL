Dark STL now reads **every Borderlands game** (Borderlands, Borderlands 2, The Pre-Sequel, Borderlands 3, Tiny Tina's Wonderlands and Borderlands 4) straight from their install folders, and puts their **guns together from their parts** on the Configure tab.

## What changed
- **Borderlands importer (Unreal Engine 3).** Add the game's install folder as it is: skeletal meshes (characters, heads, guns) and static meshes (props, map pieces) are read from the `.upk` packages in `WillowGame\CookedPCConsole` (`CookedPC` for the first game). Packages are LZO compressed; Dark STL decompresses them itself, a block at a time, so nothing has to be extracted. The first scan opens every package once and keeps what it found; later scans only open packages that changed. A mesh cooked into many packages is listed once.
- **Textures and materials.** Material instances are followed to their material; diffuse, normal and specular textures come from the instance's parameters, then from the textures the material uses (normal maps are marked as such in the game). Large mips are read from the `.tfc` texture caches beside the packages; when a cache is missing, the largest mip kept in the package is used and the model's notes say so.
- **Guns from parts (Borderlands 2, The Pre-Sequel).** Each weapon type keeps every part of every manufacturer in one shared ("gestalt") mesh in `Startup.upk`. That mesh is listed under Weapons with each part (`Pistol_Barrel_Jakobs`, `Pistol_Body_Vladof_Var1`...) as a part of the model, and each weapon type is a configurable model on the Configure tab: body, grip, barrel, sight, stock, elemental and accessory, with the options the game's own part definitions (`GD_Weap_*` packages) give. Without those packages the slots are worked out from the part names.
- **Borderlands 3 and Tiny Tina's Wonderlands (Unreal 4).** Add the install folder as it is: the models are read from the `.pak` files in `OakGame\Content\Paks` (both index layouts, zlib or Oodle compressed, AES-encrypted indexes; later `_P` patch paks win). Borderlands 3's AES key comes with Dark STL; others can be pasted in *Settings > Unreal games* or put in `unreal-keys.txt` in the game's folder. Skeletal and static meshes (their first level of detail with geometry, including LODs kept in `.ubulk` files), textures (BC1-BC7 and plain formats) and material instances followed to their parents give the diffuse, normal and specular maps. Models are grouped by where the game keeps them (weapons by type and maker, characters, enemies, vehicles, map pieces, objects); the scan only reads the paks' indexes.
- **Borderlands 4 (Unreal 5).** Read from the game's IoStore containers (`.utoc`/`.ucas`, with `global.utoc` for the engine's classes): zen packages, their imports followed through the other packages, and bulk data. Borderlands 4 cooks its objects without property names, so it needs the game's **type mappings**: a `.usmap` file for the installed version (dumped from the game with Dumper-7 or UE4SS, or shared by the community), added in *Settings > Unreal games* or put in the game's folder. Without one, models are listed but don't open, and say why. Weapon parts named the Borderlands 4 way (`DAD_AR_Barrel_01`) are recognised by reading their class from the package header.
- **Guns from parts (Borderlands 3, Wonderlands, Borderlands 4).** These games build guns from separate part meshes kept per weapon type and maker. Each type and maker is a configurable model: the body is the base and the other parts are sorted into slots (barrel, grip, magazine, sight, stock, under-barrel, muzzle, element, accessory) by the words in their names, so these configurations are marked as guessed.
- **Not yet:** *Collect into the app* doesn't copy Borderlands 4 models yet (they stay read from the game's containers), Nanite-only static meshes have no geometry Dark STL reads, and posing isn't available for the Unreal 4/5 games.

Built and tested on synthetic packages and containers made to the published layouts (UE Viewer, CUE4Parse); not yet checked on the games' own files.

## Windows
- **`DarkSTL_0.16.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.16.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.16.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
