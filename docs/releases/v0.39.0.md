**Export a model's files for review, and clearer reasons when animations can't be read.**

## What changed
- **Export model files.** Under ⋯ on a model's page (or right-click its card), *Export model files…* puts the model into one zip in your export folder, so a problem can be looked at without the game. You choose what goes in:
  - **The game's own files**: the model and everything it's read from (textures, skeleton, animations), pulled out of the game's archives as Collect copies them.
  - **Dark STL's model package**: the model as Dark STL imports it (glTF, materials, textures and sampled animations).
  - Either way, a **report** says what Dark STL made of the model: its materials and the textures they got, the UV range each material uses, its animations and why any couldn't be read, its skeleton beside the model's bones, and which of the game's paks each file came from (with any older copy a later pak replaces). The **log** of opening it comes too.
  - The zip's folders open again with *Add collected files…*.
  - Textures and animations can be left out to keep the zip small.
- **Why an animation can't be read is clearer.** The Pose tab now says how many tracks name a bone the skeleton doesn't have, the highest bone named, and how many bones the skeleton has. When animations fail for different reasons, it counts each reason.

Tested on byte-built Returnal and Dark Souls III files, including opening the exported zip again with the game removed. Not yet checked on real game files.

## Windows
- **`DarkSTL_0.39.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.39.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.39.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
