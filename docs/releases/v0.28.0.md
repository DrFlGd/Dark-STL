**Choose any texture of the game for a material, by its name.**

## What changed
- The **Materials** list on the Textures tab has a **Change…** button beside each material's colour, normal and height map. It opens the texture picker: type part of a name (`wall`, `_n`, `c1100`) to search the game's textures, see each one, choose whether it is the colour, normal or height map, and **Use it**. The model opens again with it, and Generate, Paint and Export use it like the model's own. **Go back to the texture the model names itself** undoes it.
- The picker searches the textures in the game's asset store (everything imported as model packages) and every texture the game's folders hold, where Dark STL can list them: FromSoftware games and RE Engine games for now. For other games, import the models as packages first, and their textures can be picked.
- A picked texture is kept in the game's asset store, so the choice keeps working after the game is uninstalled. The choice itself is kept in the game's **library overlay**, a file in Dark STL's settings folder (`overlays/<game>.json`) that never touches the game's files or the packages. It names the model by its path in the game, so it applies to the game's file and to the package made from it alike.

This is the second stage of the model-package plan. Next: the rest of the library overlay (your own folders, in-game names, face, body and hair combined into one model), then saved variations of generated models.

Tested on synthetic Dark Souls III and Resident Evil 4 files: a texture from a map's pack that no model names, found by name, assigned, used, kept through importing the game as packages and removing it, and undone.
