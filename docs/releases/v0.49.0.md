**Open any Unreal Engine 4 or 5 game and FBX files, tune how a game is read from a file of its own, and see the in-game names of Cyberpunk, Borderlands and Unreal games' models.**

## What changed
- **Any Unreal Engine 4/5 game.** Add the folder of an Unreal game Dark STL doesn't know and the add-folder dialog says it's an Unreal game and asks for its name (it suggests the install folder's). Its models are read like Returnal's and Borderlands 3's: skeletal and static meshes with their textures, sorted into kinds and groups by the folders the game keeps them in (weapons, characters, creatures, props, map pieces...). A game whose `.pak` files are locked says where its key goes (Settings › Game tools › Unreal games, or an `unreal-keys.txt` in its folder).
- **Game profiles.** What makes one game differ from another on the same engine is now in a small JSON file per game: how its folder is recognised, the engine release and keys, how its folders and names sort models into kinds and groups, what its texture names mean, and which of its text names its models. Returnal, Borderlands 3, Tiny Tina's Wonderlands and Borderlands 4 ship one, and Dark STL writes one for each Unreal game you add by name. **Settings › Game tools › Game profiles** lists them: *Copy to change* puts a copy of a shipped one in your profiles folder to edit, *Open the profiles folder* opens it, and files that can't be read are listed with the reason. A file there with a shipped one's name replaces it, any other adds a game; rescan the game's folder to see its models sorted the new way. The FromSoftware, RE Engine and Cyberpunk games take a profile too, to change the files that recognise them or their settings, or to add another game of that engine. The format is in `docs/profiles.md`.
- **FBX files.** Open or add `.fbx` files from Blender, Maya, 3ds Max, Unreal and the modding tools, binary or text, old (6.1) or new (7.7). Every mesh is placed where the file puts it, turned to Z up and metres from the file's own axes and units, with a part per mesh and material. Textures are found from the paths the file keeps, by name in the folder it's in, or inside the file when they were embedded. A skinned model comes with its skeleton: the Pose tab plays the file's animations and turns its bones, and Collect keeps both in the package.
- **In-game names for more games.** The library shows the names the games give their models beside the files' own, as it did for the FromSoftware games: the Unreal games' string tables (Returnal, Borderlands 3, Wonderlands, Borderlands 4 and any other Unreal game), Borderlands 1, 2 and The Pre-Sequel's text (a head or skin named *Blue Steel*), and Cyberpunk 2077's weapons from its on-screen text (*Lexington (body)*). Names you give a model still win. The RE Engine games give none yet: their text is tied to models through item data Dark STL doesn't read.

FBX files are read by Dark STL's own reader, so nothing new is installed. Tested on synthetic files: Unreal games added by name and through a profile in the settings folder, a replaced Returnal profile sorting a weapon into a new group and going back when the file is removed, FBX files in binary and text with their axes, units, textures, skin and animations, and the names from string tables, `.INT` text and Cyberpunk's on-screen text. In Chromium: adding an Unreal game by name and seeing its profile listed, and opening an FBX model with its textures and posing it.

## Windows
- **`DarkSTL_0.49.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.49.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.
