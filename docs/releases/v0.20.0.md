**Cyberpunk 2077 weapons are configurable models, put together as the game's own appearance files describe them**, and **multilayered materials are blended into real colour and normal maps**.

## What changed
- **Weapon cards from the game's appearances.** Each weapon's `.app` lists its appearances (*frank*, *military1*, *neon2*, *maelstrom*... the dropdown at the top right of a Cyberpunk model's page is that list, as the mesh carries it) and the mesh components each one draws. Those components now give the weapon's configuration under *Weapons*: the body is the base, each part the appearances swap (magazine, stock, decals, grips...) is a slot with the meshes it carries as options, the body's own appearances are a **Finish** choice, and every appearance is a preset, so picking *military1* on the Configure tab fits the parts and finish that appearance uses. Parts are placed where the appearance puts them (their local transform, on the slot or bone they are bound to).
- **Attachment points.** Slots named scope, muzzle, underbarrel and the like in the weapon's entity (`.ent`) become slots of the card, offering the game's attachment entities of that kind (`w_att_*`, `base\weapons\attachments\...`) placed at the point. Which attachments a weapon takes in the game lives in TweakDB, which isn't read, so every scope is offered on a scope slot.
- **Every part mesh has a Configure tab** that opens the weapon it belongs to. Folders without appearance files (a WolvenKit export of meshes alone) keep the guessed cards from 0.15.0.
- **Multilayered materials get their textures.** Most Cyberpunk surfaces (weapons, skin, metal) are *multilayered*: a `.mlsetup` lists up to twenty layers, each a small tiled `.mltemplate` (colour, normal, a named colour scale and normal strength), and a `.mlmask` says where each layer shows. Dark STL only found the material's global normal map before, so appearances showed no colour. The layers are now blended into one colour map and one normal map per material (2048 to 4096 texels a side, kept with the model), as the game draws them, so the Textures tab, previews and displacement have something to work from. The fine microblend grain is left out.
- **Reading appearance packages.** The component lists inside `.app` and `.ent` files are a packed format of their own (not CR2W chunks); it is read now, which also makes an entity's slot components and bindings available.

The first scan after updating reads through the game's archives once more, to note which appearance files describe weapons. Built on synthetic files made to WolvenKit's layouts; not yet checked against the game's own files, so the blended colours and the part placement are the things to look at first.

## Windows
- **`DarkSTL_0.20.0_x64-setup.exe`** installs Dark STL for your account (no administrator rights). It isn't signed, so SmartScreen asks once: *More info > Run anyway*.
- **`DarkSTL_0.20.0_x64-portable.zip`** is the same app in a folder: unzip it anywhere and run `Dark STL.exe`.

## Other systems
Python 3.10 or newer. Download the wheel below, then:

```
pip install "dark_stl-0.20.0-py3-none-any.whl[gui,remesh,fast,ai]"
darkstl
```
