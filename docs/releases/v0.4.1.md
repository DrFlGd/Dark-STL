The library no longer redraws its previews as you move around it, models whose textures are kept somewhere else in the game now find them, trying displacement settings no longer evens out the mesh again each time, a long Generate can be stopped from the status bar, and collected models can be moved and added to a fresh install on their own.

## What changed
- **Previews are drawn once.** A model's preview is drawn the first time it comes into view and kept until you **Rescan** its folder (or its file changes). Previews already drawn now show at once, a page of them together, instead of queueing behind the ones still being drawn; going back to a place, searching, sorting or switching between grid and list shows them straight away without asking the engine again. A model that can't be drawn is remembered too, so it is no longer read again on every visit (setting the Oodle library in Settings lets those try again). After this update every preview is drawn once more, so they pick up the textures below.
- **Textures found anywhere in the game folder.** Many models don't carry all their textures: map pieces and objects use their map's texture packs (`map/m24/m24_0000.tpfbhd`), armour uses shared packs (`parts/common_body.tpf.dcx`), and some characters borrow another character's archive. Scanning a game folder now lists every texture pack in it with the names of the textures inside (read from the packs' headers, so it's quick, and kept between scans so a rescan only reads what changed). Opening a model, drawing its preview, generating and exporting then use the textures it names from wherever they are; the model's notes say where they came from. The games' "no texture" stand-ins (`SYSTEX_Dummy...`) are left out.
- **Collect takes those textures too.** *Collect into the app…* writes each texture a model takes from elsewhere into the game's library folder on its own (`_textures/<name>.dds`), instead of copying a map's whole texture pack.
- **Collected files can move.** Changing the app library folder in *Settings* now moves the files collected so far there (untick *Move the files collected so far there too* to leave them where they are) and lists them from their new place.
- **Collected files stand on their own.** Each game's folder of collected files holds a small `darkstl-collection.json` (which game, where the files came from, which models). On a fresh install, or on another computer, *Add collected files…* (beside *Add a game folder…*) takes the library folder, adding every game in it, or one game's folder; *Add game folder…* recognises them too. Each game can come from its own folder or from its collected files. The dialog offers to collect new files into that folder from then on. Folders collected with 0.4.0 get their note the next time the app starts.
- **Generate's two steps run apart.** The evened-out mesh step 1 makes (at the vertex count, method and rounding chosen) is kept, so generating again with only step-2 settings changed (strength, detail maps, clean-up, colour detail and the rest) starts from it and just displaces it again, instead of subdividing or remeshing the model each time. Step 1 says so when its mesh is kept; changing the vertex count, method, *Round off curved surfaces*, the parts or the pose makes a new one. The last two meshes are kept, and one made by a Generate you stopped during step 2 is kept too.
- **Stop a job from the status bar.** Click the job at the bottom right (*Generating …*, an export, a scan or a collect) to stop it; it ends at its next step and nothing half-made is kept. With several running, *N running* lists them, each with its own Stop. The Generate tab also has a Stop button under its progress bar.
